Partial Answers#

A tool asked for several things – channels to read, entries to fetch – may answer some of them and not others. Every such tool says how much it answered in one shape, so the agent never has to work it out from prose or by comparing lists.

The rule#

A tool that answers part of a request returns the answered part plus a map of what is missing, each entry carrying the source’s own text. When nothing answered, the tool refuses with the same map. A request the tool refuses as a whole is a different error, with a different remedy.

The map#

missing maps each thing asked for and not answered to the source’s own text, in request order:

{"missing": {"SR:BPM1:X": "TimeoutError: no reply in 5 s", "e2": null}}

  • The key is what the request named: the channel address, the entry id.

  • The value is the text the source gave for that item – for a channel read, "<ExceptionType>: <message>". It is null when the source gave no text. A tool never makes a reason up.

Three arms#

What happened

What the tool returns

Some or all answered

The result, with missing beside the answered part. missing is always present; {} means everything answered.

Every item tried, none answered

An error whose details.missing holds the same map. When every item failed with the same error the controls server answers on its own – not_found, timeout_error, connection_error – that error is returned, with its own message and remedy and details.missing added. Otherwise the error type is nothing_answered.

The request refused as a whole

The refusal’s own error type (validation_error, write_refused, …), with no map: nothing was tried, so nothing is missing.

nothing_answered and a whole-request refusal ask different things of the agent. A refusal names a request to change; nothing_answered names items that were tried and did not answer, which the agent reports to the operator entry by entry.

The tools#

Two exceptions#

channel_write

A write answers with one row per channel, and each row’s outcome word says what happened to that write (see Connector Contracts). A write’s map is its rows. It has no missing key: a written but unconfirmed channel was answered, and a second map would state the refused and failed rows twice.

archiver_read

A channel with no points in the requested window is answered, not missing: the data file has its column, and the coverage block says from the archive’s own facts why the window is empty.
