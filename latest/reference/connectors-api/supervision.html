Supervising Connector Processes#

What a supervisor needs to run connectors in child processes: the connector host’s launch, proxy and pool, starting and stopping children, and the policy for a call that failed.

Inter-process plumbing for the connector-host child.

The child process owns the control-system client library; the parent talks to it over a pipe pair. This namespace holds what a supervisor needs: launching and stopping a child, the proxy that drives one and the pool that keeps them, the endpoint derivation and verification of what a child reports, and the two errors the wire format raises when a frame cannot be written or read. The wire codec itself and the typed-exception registry that carries a failure across the boundary are internal to this package (_frames, _exceptions).

The frame errors are imported here. Every other name is resolved on access (PEP 562): the child runs as python -m osprey_connectors.ipc._host, and a package that imported _host eagerly would load it a second time under __main__.

osprey_connectors.ipc.host_env()[source]#

The environment a child is launched with: os.environ, minus EPICS.

The child scrubs EPICS_CA_*/EPICS_PVA_* again on its own first line, and that is the scrub the design depends on. This one is the defense-in-depth half: an ambient gateway never reaches the process that could act on it, so no window exists between exec and scrub.

The child is stamped with ENV_CHAIN_APPLIED_ENV. Reading its config file would otherwise load the project .env from its working directory after the scrub, and an EPICS_* line there would put back what both scrubs took out.

START_MARKS_FD_ENV is dropped too: a supervisor that is itself running under one never passes on a descriptor number that names something else in its child.

A write missed its deadline and its child was killed for it.

Raised only by a pool built with kill_on_write_timeout=True, only to the write whose deadline passed, and whether or not the child would have answered a ping (cause="write_timeout"). A TimeoutError like ConnectorHostUnresponsiveError, because that is what the write would have raised in-process: it may or may not have landed. class osprey_connectors.ipc.ConnectorHostProxy(reader, writer, *, timeout_grace_s=1.0, deadline_s=None)[source]#

Bases: object

A connector-shaped handle on the connector running in the child process.

Parameters:

  • reader (Any) – Anything with await read(n) -> bytes returning b"" at EOF — an asyncio.StreamReader, and therefore an asyncio.subprocess.Process.stdout.

  • writer (Any) – Anything with write(bytes), await drain() and close() — an asyncio.StreamWriter, and therefore an asyncio.subprocess.Process.stdin. wait_closed() is used when present.

  • timeout_grace_s (float) – Extra time the proxy waits beyond a call’s own timeout before giving up locally. The child applies the timeout to the control-system call itself and reports its own TimeoutError, which is the more informative one; the local deadline exists only so a wedged child cannot hang a caller forever. Set it to 0 to make the local deadline the only one.

  • deadline_s (float | None) – Local deadline for a call whose timeout is None. Never sent to the child — the connector keeps its own default — and None (the default) means such a call waits as long as the child takes.

The transport is duck-typed rather than a subprocess handle so tests can drive the proxy over a socketpair, and so the supervisor can hand it a process’s pipes without this class knowing anything about process lifetime. from_process() is the convenience for the latter.

async disconnect(*, ack_timeout=2.0)[source]#

Ask the child to release its connector, then close the pipe.

Idempotent and never raises: it is called from teardown paths and from the switch’s failure branch, where a second exception would only bury the first. Send one supervisor request (init, ping) and await its reply.

Not part of the connector surface: a supervisor that brings a child up over this proxy’s pipes, or asks whether it is still alive, uses this, so the reply is demultiplexed and its error decoded by the same plumbing every other call uses. osprey_connectors.ipc.verify_host_report(derivation, report, *, readonly_run=None, writes_enabled=None)[source]#

Assert the child came up where the derivation said it would.

Given the posture the derivation was taken under (readonly_run, writes_enabled), the report is first held to it: its connector_type and its transport must be the derived ones, and then a readonly run requires the report’s readonly_run to be True while any other run requires its writes_enabled to equal writes_enabled. With neither given, only the endpoint check below runs.

verify_child_report() answers this for every target whose config names a gateway. A deployment can also select a connector that talks to no gateway at all — the simulator served in process is one, and it is the fail-safe default — and for that one the derivation has no endpoint and the child reports none. Nothing is verified there because there is no endpoint to get wrong, but the symmetry is: a child that configured Channel Access where the config derived nothing has inherited an environment from somewhere, and that is a mismatch as serious as any other.

The unverified branch is entered only when the derivation has no endpoint rows at all. A target with rows whose selected role is missing — a write-only gateway table on a deployment that selects read_only, say — is a gateway deployment with a hole in it, not a gatewayless one: its child connects to a real control system over whatever default broadcast address it finds, and that is precisely the unpinned-CA case verification exists to catch. It goes to verify_child_report(), which refuses it either for reporting no gateway or for having no derived endpoint to compare against.

Parameters:

  • derivation (TargetDerivation) – The derivation for the target, from derive_endpoints().

  • report (dict[str, Any]) – The child’s post-connect report.

  • readonly_run (bool | None) – Whether the derivation was taken for a readonly run.

  • writes_enabled (bool | None) – Whether the derivation was taken with writes armed.

Returns:

A passing Verification, or a failing one naming the field (connector_type, transport, readonly_run, writes_enabled or an endpoint field), the expected value and the value the child reported.

Return type:

Every child a supervisor starts is put down the same way, and this module is where that way is spelled once: terminate() puts down one child. Two invariants hold throughout:

  1. Nothing signals a child before the event loop has had the chance to reap its exit.

  2. Every exit code reported comes from a reap.

It imports only the standard library and knows nothing about the control system its callers talk to.

What a supervisor does about a connector call that failed: one policy, one table.

A supervisor owns a connector’s lifetime: the connector-host pool owns its children, a server owns its connectors. A supervisor that calls the policy — the connector-host pool does — hands the error and the supervised connector to RecoveryPolicy.recover() when a call fails, and the policy answers with what it did, as a Recovery record, or None when the failure restarts nothing.

The decision is one table, failure class and origin in, one step out:

  • a connector bug (ConnectorInternalError), a failure about one channel (ChannelError), a batch read that failed (ChannelReadFailedError) and a refused client library (ClientLibraryRefusedError), from anywhere: none;

  • a TimeoutError on the link: replace for a write when writes replace, probe otherwise;

  • a lost connector (ConnectorUnavailableError) and a bare ConnectionError, from anywhere: replace;

  • anything else, a TimeoutError from the child or from this process included: none.

A failure under one of the three contract roots of osprey_connectors.errors (a channel failure, a lost connector, a connector bug) is decided by its root alone; the builtin rows decide only a failure under no root. So no failure reaches two steps, and no decision depends on the order of the rows.

Probe pings the incarnation: one that answers is kept (child_kept), one that does not is replaced. Replace retires the incarnation under Timing.LAZY (the next call starts a fresh one: child_replaced for a child, connector_dropped for an in-process connector) and respawns it under Timing.EAGER (child_replaced, or respawn_refused when no new child could be brought up).

Invariants:

  • Callers hand over the error; the policy decides where it came from. An error the connector-host child sent is _Origin.CHILD, one the link to the child made (a missed deadline, a closed pipe) is _Origin.LINK, and anything from a connector in this process is _Origin.IN_PROCESS.

  • Recovery happens at most once per incarnation. Every failure of one incarnation awaits the one act the first started, and an incarnation that has been replaced or dropped is answered with that record and never acted on again.

  • One attempt per failure episode. A refused respawn answers every call that began before the refusal; a call that begins later may try once more. A kept child is no episode’s end: its next missed deadline pings it again.

  • The policy never retries a call, owns no deadline, and holds no incarnation alive.
