Simulation#

The simulated machine behind the virtual accelerator. The package root imports neither numpy nor lume; the heavier modules are imported by their own names.

The simulated machine behind OSPREY’s simulator connectors.

The package root holds only what every reader needs without loading a model: the tick period and the fast period of timed passes, char-waveform decoding, the gated and labelled value types and the model status lookups. It imports neither numpy nor lume; the active-scenario state, value coercion, the composite, the texture engine, the archive and the series primitives are imported from their own modules.

The active scenario set and the composition rule scenarios must obey.

Every reader of the active set — sim apply, the archive, the composite and the stand-in — resolves it and checks it here, so they cannot disagree on which scenarios run or on which sets compose; sim apply writes it here too, with write_active_state().

Scenarios compose only when they write disjoint targets: two scenarios writing one target would apply in an order-dependent way, so such a set is refused as an Overlap naming the target. A scenario’s still meets only the motion other scenarios set: it overlaps the noise or couple of the readings it stills, never another target and never another still. An archiver entry writes no target: events several scenarios script on one channel compose in set order in the archive, so they never refuse a set. A process that serves without a scenario because of an overlap logs one overlap_record(), and readers print it with format_overlap_record().

The module imports neither numpy nor lume.

The simulator view a build writes, and the one reader of it.

osprey build writes each render’s simulator view into <render>/data/simulator/; this module names its files and their schemas and opens it. Every reader of a view opens it through SimulatorView, which refuses a file whose schema is not the one this OSPREY reads, so a render from an older OSPREY is rebuilt rather than misread.

A wiring record of a physics model carries what its engine’s describe() stated at build time: its engine_role (one of ENGINE_ROLES), the transverse plane it steers or reads (x, y or None), its refresh (one of REFRESH) and, when it carries any, its marks (of MARKS). The words are the facility schema’s. A readback is any read of an element’s setting, paired with a setpoint or not; a reader wanting the readback of a setpoint reads that setpoint channel’s pair.

The module imports only the standard library and osprey_connectors, so a reader that must not load a model can open a view.

Materializing a deployment’s archive: the base seed and its fingerprint.

A deployment that serves simulated channels needs history for them, and the honest way to have history is to store it. This module computes that stored history and writes it: one document per timestamp carrying every channel, over a two-tier grid reaching back the configured retention, in the schema MongoDBArchiverConnector already reads.

The values are not this module’s invention. Every channel is read from the archive composite (build()), the simulator view’s composite at the start state of the active scenario set, evaluated at each document’s own absolute timestamp. Every sample is a pure function of (channel, epoch seconds) under that set, so a document written here at time T holds exactly what the composite serves at T: seeded history and the served machine are one world rather than two plausible ones.

Three pieces of the design are worth stating outright:

  • Two tiers, one grid. The coarse tier spans the full retention window; the dense tier adds samples between its points over the recent span. They are built from one epoch-aligned grid and the dense tier skips timestamps the coarse tier already owns, so no timestamp is written twice — the schema is one document per timestamp and a duplicate would be a second, competing sample.

  • Retention is per document, not per collection. Each document carries an expireAt that a TTL index acts on, stamped by the tier that produced it. A coarse sample lives for the retention span, a dense one until it ages out of the dense span, and a document with no stamp at all never expires — which is what lets a later scenario rewrite protect the windows it touches by simply removing the field.

  • Reseeding is a decision, not a default. A seed manifest records the knobs the store was built with, and compare_fingerprint() reports match, mismatch or absence. The seed instant is stored but deliberately excluded from the comparison — it differs on every deploy, and including it would make every deploy a reseed.

This module never imports pymongo: the functions that talk to a store take a collection handle their caller opened. That keeps an optional dependency optional, and leaves the grid, the fingerprint and the synthesis — the parts worth reasoning about — pure and testable with no store at all.

The archive composite. build() reads a simulator view’s history through a composite of its own, built at the start state of one active scenario set: the set’s active writes, never a session write. The composite is read once, one solve per physics model, and ArchiveComposite then computes every timestamp from those held values: the active scenarios’ archiver events, then the texture’s drift, couplings and keyed noise, the physics engine’s readout and the clamp, as the composite serves them. Samples are in the wire representation, so a bool or enum channel archives its option index. lume is imported inside build() only.

How far a simulated channel’s declared motion can carry its value.

A channel’s seed may declare two kinds of motion: noise, a Gaussian draw, and drift, a slow wander whose amplitude bounds it (|wander| <= amplitude by construction). A noise record states exactly one term: {absolute: <sigma>}, a sigma in the channel’s unit, or {relative: <fraction>}, a sigma as a fraction of the reading. An active scenario may couple the channel to shared drivers, each adding gain * (1 + gain_wander) * driver with |driver| <= drive.amplitude, and may replace its noise.

A served value is therefore the held value plus at most its envelope:

|drift.amplitude|
  + sum |gain| x (1 + |gain_wander.amplitude|) x |drive.amplitude|
  + _MOTION_SIGMAS x noise sigma
  + tooth depth

where a relative noise sigma is taken at the seed’s own nominal, or at the level a topoff seed holds, and the tooth depth is how far a topoff seed’s sawtooth carries the reading from that level. A channel that declares no motion, or that an active scenario stills, has an envelope of 0.0.

The module imports only the standard library and the standard-library-only topoff, so the build, the simulator view’s reader and the texture model share one rule.

The pulsed-septum current trace: one pure function of address, time and drive.

A pulsed supply fires about once a second; each firing is captured as a fixed window of 500 samples. The pulse has a fast rise, a flat top that droops slightly, and a slower exponential fall. The flat top rings: a few damped sinusoids whose amplitudes and phases are drawn fresh for every shot, together with a small per-shot jitter of the rise edge. On top of that sit a slow amplitude drift and a slow timing drift (periods of minutes) and a small sample noise, all keyed by the channel address and the epoch millisecond, the same way the texture engine keys its motion. That is what lets the live server and the seeded archive produce the identical trace for the same instant.

The trace is linear in the driver level (the supply setpoint): every term, noise included, is a multiple of it, so the peak ratio of two traces at the same instant equals their driver ratio. A disabled supply reads flat zero.

The shape constants live here, not in seeds. SHAPE_VERSION is a digest of them; the archive seed fingerprint consumes it, so changing the shape re-seeds the stored history.

The top-off sawtooth: a stored current that decays with a lifetime and refills on a period.

A topoff seed {ceiling, lifetime_h, period_s} describes a float channel that starts each period at ceiling and decays exponentially with the lifetime tau = lifetime_h * 3600 seconds until the next refill. The unit shape is a pure function of epoch seconds:

s(t) = exp(-((t mod period_s) / tau))

so every channel with the same seed refills at the same instants, and a live read and an archived sample at the same instant agree. Its mean over one period is:

m = (tau / period_s) * (1 - exp(-period_s / tau))

The channel HOLDS the level ceiling * m – the value a limits band and an archive’s start state see – and the sawtooth is MOTION around it: the tooth level * (s(t) / m - 1), added on the level it rides, so at the held level the reading is ceiling * s(t), and a level moved to zero carries no tooth at all.

A topoff_lifetime seed {of} names a channel whose seed is topoff and holds that seed’s lifetime_h as a constant: the lifetime readback that produces the decay.

The module imports only the standard library, so the envelope rule and the facility build share it with the texture model. SHAPE_VERSION is a digest of the shape constants; the archive seed fingerprint consumes it, so a change to the shape re-seeds the stored history.

The texture model: the simulator’s value for every channel no served model wires.

TextureModel is a LUMEModel built from two documents of the simulator view, variables.json and seeds.json. It owns the VALUE of a channel whose owner is texture or names a model the view marks unserved, and the MOTION (keyed noise and drift) and clamp of every channel the view declares, so a served model’s readbacks can carry the same motion.

A texture channel reads clamp(held + drift(t) + couplings(t) + noise(t)). held starts at the channel’s nominal: the seed’s nominal, else the unserved model’s wiring default, else the zero of the channel’s value_type. A paired readback starts at its setpoint’s nominal. A linear channel holds the weighted sum of its inputs’ held values, a linear input counting as its own sum. Noise and drift are pure functions of the address and the epoch millisecond, so a live read and an archived sample at the same instant agree. Writing a setpoint holds the value and echoes it into the readback its pair names.

A noise record states one term: {absolute: sigma} adds sigma times a keyed normal draw, and {relative: f} adds f times held + drift + couplings times one. The active scenarios add motion through TextureModel.set_motion(): a coupled channel adds gain * (1 + gain_wander(t)) * driver(t) per coupling, where every channel coupled to one driver sees the same driver(t), and a scenario’s noise record stands in for the seed’s while it is held, drawing from its own stream. A reading the active scenarios still serves its held value: no drift, couplings or noise.

A waveform channel whose seed states pulse: {driver, enable} reads trace() at the read time, scaled by the driver’s held value and switched by the enable channel’s held label, so it moves on every read. Every other waveform channel reads its held array.

A float channel whose seed states topoff: {ceiling, lifetime_h, period_s} holds the level ceiling * m of topoff and carries the tooth level * (s(t) / m - 1) as motion on that level, so it reads ceiling * s(t) at the held level and a stilled one serves the level. A channel whose seed states topoff_lifetime: {of} holds the named topoff seed’s lifetime_h.

A channel whose seed states gate: {inputs, gated} holds its gated value while any input holds its blocking label, and its value by the rules above otherwise. gated is typed by the channel: a float holds its value times the factor gated, so a gated reading keeps a small residual and its motion; a bool or enum holds the label gated; an int holds the integer gated. An input is read as its own held value, gate included, and an input the model does not hold never blocks. The gate is part of the held value, so a read, TextureModel.held() and every reader built on it – the archive seed, a subscription comparing held values – see it alike.

The composite: one LUME model serving a simulator view’s every channel.

Composite reads the simulator view a render writes under data/simulator/ and serves its channels through two kinds of child:

  • one physics child per served model whose engine is not texture, built by the engine plug-in the osprey.simulation.engines entry-point group names, through build(model, wiring, deck, settings, active=...);

  • the texture, a TextureModel holding every other channel and the motion of all of them.

supported_variables is the channel addresses of addresses.json and its status addresses, <code>:SIM:<model>:STATUS, one per physics child. Each child’s own variables that no channel names (faults, optics) are reached as <model>/<name> through Composite.model_get() and Composite.model_set() only.

Reads. A physics readback of type float reads truth + motion(address, t), passed through the child’s readout when the engine exports one, then clamped; the readout always sees both readings of a monitor, so a read of one plane reads its partner too. A texture channel reads as the texture serves it. A reading the active scenarios still has no motion: a physics readback reads its truth through readout and clamp, a texture channel its held value. Composite.get() returns each value as its variable declares it, a waveform as an array of the variable’s dtype and shape. Composite.held() reads every channel without motion or readout.

Writes. Composite.set() coerces each value to its channel’s value_type, then sets the physics children in name order and the texture last. When any child refuses, every earlier child gets its previous inputs back and the refusal is raised as a WriteRefusedError (a ValueError) carrying the child’s text and, when one channel was refused, its address. A setpoint the active scenarios hold (stuck or disconnected in channel_faults) accepts a write, reads the value written, and forwards none of it; its readback shows the model where it was.

Channel faults. A frozen reading reads the value it served when its scenario became active. A disconnected reading reads not-a-number when it is a float, else the value it served when its scenario became active; a disconnected setpoint’s readback is that reading, and a setpoint that is its own readback reads its demand. Composite.output_severity() names every disconnected reading with the udf condition. A channel fault acts on live reads, writes and severity only; Composite.readings() serves history without it.

A model with no deck. A model whose record names no deck and wires no channel is not built: there is nothing for an engine to serve, and the facility describes such a machine so that its channels are the texture’s. Its status is no deck (STATUS_NO_DECK), its log records an unbuilt event, and it is no failure.

A failed child. A child whose engine raises while it is built or read is failed, with the engine’s error text as its status (ok otherwise), capped at _STATUS_MAX_BYTES UTF-8 bytes. It holds the inputs written to it and never raises: its setpoints read those inputs, its float outputs NaN, any other output its last good value or its type’s zero, and Composite.output_severity() names each of its channels. A refused write leaves a child as it was. A failed child is rebuilt on Composite.reset() and on a change of the active scenarios.

Scenarios. The active set is the active_scenarios file of the state directory, re-read when its modification time changes. A change rebuilds every physics child with the active scenarios’ writes and fault seeds as its start state, and hands the texture the active writes it owns and the active drivers, couplings and noise replacements; session writes are dropped. The readings any active scenario’s still list names, nominal included, are stilled. A set whose scenarios touch one target twice is served without its scenarios.

Evolution. A composite built with evolve=True drives the children whose engine states the time contract (advance, next_deadline, emitted, client_write), each looked up on the engine the way readout is: it calls advance(model, t) at its clock’s reading right after it builds or rebuilds a child, right after Composite.reset(), and before every read and write; Composite.next_deadline() is the earliest of the children’s deadlines and Composite.emitted() the union of what they emitted, drained. Only a write through Composite.set() that reaches a child’s model is a client write, handed to client_write(model, values, t); Composite.restore(), the start state and the scenario writes are not, and neither is a write a stuck or disconnected setpoint holds. A rebuild discards what a child had pending. Built without it, the default, the composite calls none of the four names.

The model log. Each physics child appends JSON lines {instance, pid, ...} to var/simulator/<model>.log under the repo root of the loaded config, one os.write per record of under _LOG_RECORD_MAX_BYTES bytes. Without a loaded config the records go to the process logger only.

osprey_connectors.simulation.logbook.parse_log_attachments(prefix, raw, bundle)[source]#

Resolve a logbook entry’s attachments list to the pictures it carries.

Each item holds exactly one key. {"path": "<relative path>"} names a shipped picture: it must name an existing file with an image suffix that starts with that image format’s signature. {"plot": "<relative path>"} names a plot spec: a .json file holding a valid spec (see parse_plot_spec()). Either path is relative to the bundle directory and must stay inside it, and no two pictures of one entry may share a file name, so a misnamed, missing or malformed picture is a load error rather than a seed failure.
