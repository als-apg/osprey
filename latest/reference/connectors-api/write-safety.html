Write Safety#

The records and verdicts a write passes before anything is put: the read-only run, the write switch, a program’s bounded write authorization, held sessions, the refusal words, which machine a write lands on, and waiting for a readback to settle. Safety Chain describes how they fit together.

The read-only run, as the environment carries it.

A deployment started read-only, and the python executor’s sandbox subprocess for a run submitted with execution_mode="readonly", both set POSTURE_ENV_VAR to SANDBOX_MODE on every process they own. This module spells that variable and the one value that sandboxes, and answers the question every write path asks first: is_readonly_run().

It is a leaf: it imports nothing from this package or the framework, so the control-system connectors, the posture store, the connector host and the framework’s audit and executor layers can all ask it without importing each other. The stdlib-only PreToolUse hooks cannot import it at all and restate it in osprey_target_state; a parity test holds that copy equal to this one.

It is not osprey_connectors.posture_store, although that module’s write_verdict() asks it first: the posture store reads the deployment’s record from the agent-data root, while this answers from the environment alone, so it can be asked before any config or file is read, and from processes (the connector host, the executor’s sandbox) that must not load the record reader to know they are read-only. An operator’s narrowing of ONE control target is deliberately not here: it never lived in the environment.

osprey_connectors.posture_env.is_readonly_run()[source]#

True when this process must refuse control-system writes, whatever it is.

Two things set OSPREY_EXECUTION_MODE=readonly, and this answers yes to both:

  • the deployment, when the whole run is started read-only — the variable is on every process the deployment owns, the MCP servers included, so a channel write is refused by the connector itself rather than only by the (best-effort) hook chain;

  • the python executor, onto the sandbox subprocess of a run submitted with execution_mode="readonly" — so the per-run claim is enforceable at runtime, independent of the pre-execution pattern scan.

Both are refusals; only the operator-facing wording differs, and the control-system base class decides that by which process is asking, because the two are the same variable at the same value.

This is the first term of osprey_connectors.posture_store.write_verdict() (readonly_run). Outside these two the variable is unset or readwrite, and the answer is still not “writes” by itself: the deployment’s control_system section and the control-context record both apply, through the rest of that verdict.

The comparison is by VALUE, never presence: readwrite is the writes posture, and a stale or misspelled value must not silently sandbox anything.

The write-switch reader — one field of one record, one verdict.

An operator sets one control target’s writes to off, asked or allowed from the header chip: “writes on for the stand-in, leave the virtual accelerator alone”. That switch is one field of the control-context record (osprey_connectors.control_context) and is enforced at write time rather than delivered by respawning the agent, which is what lets a flip land on a session already mid-conversation.

This module is the canonical reader of that field. Two others answer from the same file and must agree with it: the controls MCP server (which imports this one) and the stdlib-only PreToolUse hook in osprey/templates/claude_code/claude/hooks/osprey_target_state.py, which cannot import anything and therefore restates the contract below. Treat the following five rules as the contract; a change here is a change there.

1. Where the file is. One directory per identity: acting_identity() under STATE_DIR_NAME under the agent-data root, so one directory answers “control state for whoever this process is acting as”. The switch is one operator’s, not the deployment’s, and a single shared directory would make one user’s chip decide every other user’s writes. The directory resolves by ONE ladder, used by every writer and every reader:

  • CONTROL_CONTEXT_DIR_ENV_VAR when it names a non-blank path — the container’s own state directory, bound in by compose. It is already the per-identity directory, so nothing is appended to it: a container sees its own dir at a path that has nothing to do with the host’s tree, and deriving the identity hop inside it would name a directory nobody binds;

  • otherwise _AGENT_DATA_ROOT_ENV_VAR when it names a non-blank path — the stamp a session child carries — else resolve_shared_data_root(), the config derivation the state file has always used; and then the two fixed hops, STATE_DIR_NAME and the acting identity.

There is no third path and no fallback. A root that resolves to nothing makes state_dir() None, which a route surfaces as store_unavailable rather than quietly writing somewhere a reader will never look, and which write_verdict() refuses as record_unavailable.

2. What the shapes mean. The record’s switch field is a per-target map of positions, and switch_position() is its one reader: a machine is armed only at "asked" or "allowed", and a stored "on" from an older release reads as "asked". Everything else — no record, a record that does not name the machine, any other value — is that machine’s writes off. The record’s posture field is a mirror of the switch kept for readers that predate it, and no verdict reads it. parse_posture_value() is the grammar of that mirror, applied by parse_record() rather than restated there.

3. How a write is decided. write_verdict() is the whole rule: one total order of terms — read-only run, tier, target, owner, owner tier, record, switch, launch pin — and the first that refuses names the reason. Its order is shared with the hook’s stdlib twin, so a write is refused for the same reason on both sides. An allowed verdict carries the effective position: the stored one, capped by the ceiling the environment’s verdict already evaluates — the section’s tier on a host, the owner’s rung under a bound tree. A position above the ceiling refuses nothing and stays on disk. backstop_verdict() is the floor for a write no target or owner can be named for: its first two terms and nothing else, so it reports no position.

Both are blind to a session’s hold, because they also choose the gateway a connector child connects on. The hold is decided where a write executes: session_hold_refusal() asks it alone, and execution_verdict() is write_verdict() with the hold placed after its first two terms.

The switch is a property of one OWNER’s record, not of a process tree: no session key indexes it, and a process that belongs to no session — a dispatch worker, a CLI run — is decided by the same field as one that does. OSPREY_POSTURE_SESSION remains the audit session id and nothing more.

Inside an executor sandbox one further term is read, and only there: LAUNCH_POSTURE_ENV_VAR, the switch state the run was LAUNCHED under (launch_posture_stamp() writes it, _launch_pin_term() reads it). Its job is asymmetry: a machine switched off mid-run is refused by the record read, while a machine switched ON never reaches a run that started with it off, which would otherwise hand a running script write access the operator had not given it when the run began.

4. When a change is seen. Every read re-stats the record and re-parses on (st_mtime_ns, st_size, st_ino) — the cache lives in control_context, and its invalidate_cache() is the hook a process that moved roots (or a test) drops it through. A missing record is every switch off, not an error.

This module reads no config for the switch, holds no cache of its own, and imports nothing from osprey: it runs inside the connector-host child and the executor sandbox, where the dependency budget is the lean connector chain. The record reader is imported inside the functions that need it, because the import direction between the two modules is one-way — the record module imports THIS one at module scope for the root and the grammar.

5. Whose switch decides. A chip is one person’s, so a verdict needs a name as well as a target. That name is the OWNER, and it is resolved by one ladder here — current_owner(), with NO_OWNER for work that belongs to nobody — so that the write monitor and the queue never disagree about whose switch a plan runs under. The owner of a queued plan rides on the item as RESERVED_OWNER_KWARG and is bound for the wrapper’s body by bind_owner().

A container that holds no chip of its own — a lane’s queueserver, the dispatch worker — reads that owner’s record out of a read-only bind of the WHOLE tree, CONTROL_CONTEXT_TREE_ENV_VAR, rather than out of a directory of its own. That read fails CLOSED: an unprovisioned mount, a group the container could not join and a record written 0600 must not be answered as an operator who switched nothing on, nor as one whose switch nobody could read being on. So the tree reader separates the one absence that is an answer — no record for this owner, every switch off — from every failure on a path that is THERE, which refuses as record_unavailable. CONTROL_TREE_MARKER_NAME is what makes the first question answerable at all: a bind whose source does not exist is created empty by the container runtime, and an empty directory says nothing about whether it was ever built.

The invariant that binding rests on: the owner variable is read on the connector’s async path, never after a thread or executor hop. A context is copied into a task when the task is created, so the binding reaches everything a RunEngine schedules from the wrapper’s context. An offload is where that stops being true, and which helper made it decides whether it does: asyncio.to_thread copies the context and carries the binding into the thread, while loop.run_in_executor, a raw executor submit and a bare threading.Thread do not. No gate may depend on the carrying one having been chosen. A verdict taken behind such a hop would read NO_OWNER; every verdict is therefore taken before the offload.

The absence of an owner: one instance, compared by identity and nothing else.

None cannot carry this meaning, because current_owner() already uses None for “the caller named nobody, so walk the ladder” — a different question from “the ladder ran out”. A string cannot carry it either: every string is a name some deployment may legitimately give an account, so an owner spelled "" or "none" would be indistinguishable from a real one at the directory a verdict reads.

There is deliberately no parse in the other direction: nothing turns "<no owner>" back into this value. The string form exists so that a warning line about an owner-less plan can print it — a raising __str__ would cost the one line that says the plan ran for nobody — and printing is all it is for. Callers ask owner is NO_OWNER, never truthiness (a real name can be falsey only by being empty, which this module never produces) and never equality with the text.

osprey_connectors.posture_store.bind_owner(kwargs)[source]#

Bind the owner riding on kwargs for the body, yielding the kwargs without it.

The one way an owner enters a queueserver worker: the bridge puts it on the item as RESERVED_OWNER_KWARG, the worker hands those kwargs to the plan wrapper, and the wrapper runs its body inside this block. The yielded mapping is what the plan’s own signature is validated against — the reserved key is gone by then, so a plan never sees an argument it does not declare.

kwargs itself is not mutated. The caller keeps whatever it was handed, and two wrappers reading the same mapping cannot race over who pops the key.

A missing key, a blank one, or one carrying anything that is not a string binds NO_OWNER: the plan reached the queue without a name, and no login’s switch can cover its writes.

The reset is an assignment to NO_OWNER, not a token restore. Plan wrappers are generators, so the set and the finally can run in different contexts, and a token from one context cannot be reset in another. There is nothing to restore in any case: owners do not nest — a run belongs to one person or to nobody — so the floor is the only correct value to leave behind, and leaving it is what stops one run’s owner from gating the next run’s writes.

osprey_connectors.posture_store.current_owner(owner=None)[source]#

The owner whose switch decides a write, by a five-rung ladder.

Most specific first:

  1. owner when the caller named one, stripped — the same normalisation the two rungs below apply, so a padded name and a bare one address one person’s directory rather than two. Passing NO_OWNER explicitly is naming one — it says “this work belongs to nobody”, which a verdict refuses — which is why the “unnamed” spelling is None and not the sentinel. A caller that names an owner with no name ("", or only spaces) is answered with that empty name rather than falling through to the rungs below: the fall-through is for a caller that named nobody, and a name no directory can hold is a lookup that fails rather than one that is not attempted.

  2. The bound context variable, set by bind_owner() from the reserved kwarg a queued plan carried. This is the rung that makes a lane’s plan obey the chip of the person who queued it.

  3. CONTROL_OWNER_ENV_VAR, the stamp a dispatch job’s environment carries. Always answered as a str; a blank or whitespace-only value is the unset case spelled differently — a rendered-but-empty environment: entry — and falls through rather than naming an owner with no name.

  4. NO_OWNER for a dispatch run (DISPATCH_RUN_ENV_VAR is "1") that none of the rungs above named an owner for. The account a scheduled job runs as is not a person, so it never stands in for one.

  5. Otherwise: NO_OWNER when a tree is bound (_tree_is_bound(), the one spelling of that question), else acting_identity(). A container holding the tree holds no chip of its own, so the account it runs as is not an answer; anywhere else the process account is the person whose chip the record was written from.

Never raises: this is read on a write path, and a lookup that cannot name an owner must produce a verdict rather than an exception.

A program’s bounded write authorization: which channels, which values, how many writes.

The write switch is a person’s gesture over a whole machine. A program such as an optimizer needs less than that and must get no more: an authorization (a grant) names one machine, the login whose switch it stands in for (the owner), the identity that may use it (the holder), a closed range per channel, a budget of write steps, a hard expiry, a lease the holder renews, and who approved it. Every write the holder makes is checked against it; it ends at an exhausted budget, an expiry, a lapsed lease or a stop, and nothing renews the budget. The machine’s switch may stay off throughout.

This module owns the two files, their readers and their writers, and the verdict. The write guard of every control-system connector (ControlSystemConnector) asks authorized_execution_verdict() for every write call of a process that names an authorization (AUTHORIZATION_ENV_VAR), spending its step, and the connector-host pool sets that variable for a child whose key names one; a gateway choice and a child’s report take authorized_write_verdict().

1. Two files, two writers. The grant is <authorizations dir>/<id>.json, written once by the approver’s process and afterwards only to mark it revoked (_issue_grant(), revoke_grants()). The authorizations directory is the owner’s: AUTHORIZATIONS_DIR_NAME inside the owner’s directory of the read-only control-context tree when one is bound, else inside this host’s state_dir(). The ledger is <ledger dir>/<id>.ledger.json, written only by the holder: the holder opens it with its lease (start_lease()), its heartbeat renews the lease (renew_lease()), and the connector child appends one step per write call (_spend()). The ledger directory is LEDGER_DIR_ENV_VAR, else, on a host with no tree bound, the host’s authorizations directory; under a bound tree with no ledger directory there is none, and every write refuses. The control-context record is not touched: control_context.json keeps its schema and its seven fields.

2. Reads fail closed. Both files are read the way the posture store reads the tree (_read_tree_context()): no symbolic link is followed at any directory below the root or at the file (the file is opened O_NOFOLLOW), the read is bounded, the file must be a regular file, and the payload must be exactly this schema — every field present, of its type, no other field, no repeated key, every number finite. A grant that is absent is no authorization (switch_off); every failure on a path that is there refuses (auth_unreadable), and so do a missing or unusable ledger directory and a ledger that cannot be read. A ledger that is absent has no lease, and refuses auth_lease_lapsed.

3. The verdict. _verdict() judges one write call — a whole batch of (channel, value) operations — in one total order: the launch pin (_launch_pin_term(), read here because the switch verdict reaches it only with the switch on), the owner, the record, the grant, its holder and owner, its machine, a stop, its expiry, the switch position for a self-issued grant, every channel listed and every value a finite number in its range, the lease, and a step left. It does not repeat the switch verdict’s earlier terms; authorized_execution_verdict() is the composition a write path takes: the execution verdict first, and for a process that names an authorization, whenever that verdict allows or refuses only switch_off, this one in its place. An authorization never lifts a tier, an unknown owner, an unreadable record, a pin or a hold, and a person turning the switch on mid-run never lifts the bounds.

4. One write call is one step. _spend() takes the ledger’s lock (an exclusive flock on <ledger>.lock beside it, as session_hold takes its record’s), re-judges the whole verdict against the ledger it read under that lock, and appends the step through atomic_replace() before it answers. The caller writes only after an allowed answer, so a crash between the two costs the step and never writes unbudgeted. Concurrent appenders in any number of processes on one kernel are serialised by the lock.

A step is spent before the connector’s own checks run: a write the limits database then refuses has still spent it, and so has one whose put fails. Both fail closed. A stop that lands after a write call’s verdict and before its put does not reach that one call, which goes out as judged; the next call is refused. The switch’s own verdict has the same window.

5. The lease. The holder renews lease_until_ns; a lease that lapses ends the authorization for good — renew_lease() refuses once it has lapsed. Where the reader shares the holder’s PID namespace, the holder’s PID, its start time and its state are also asked (_pid_namespace(), _process_start_time()): a dead, reused or zombie PID lapses the lease before its time. From another namespace the lease time alone decides.

6. Self-issue at ``allowed``. A holder whose owner’s switch stands at allowed for the machine may write its own grant into its ledger directory (self_issue()), with approver surface write_switch. Such a grant is honoured only while the position stays allowed: the first write after it leaves allowed is refused and lapses the lease, so the switch coming back does not revive it. A grant found in the ledger directory that claims any other surface is not honoured at all, because the holder can write there.

7. Overlap. Two programs steering one channel of one machine is never what an approver meant: _auth_overlap() finds the live grant of another holder sharing a channel, and _issue_grant() refuses auth_overlap under the directory’s lock, so two approvals cannot both pass the check. A grant whose every ledger in sight shows its lease time passed, by a grace for clock skew, does not count: no write may use it. This assumes a holder keeps one ledger directory per authorization; start_lease() refuses only a ledger already in its own directory, so a second lease under the same id elsewhere is not covered. The check reads the owner’s own directory and the holders’ self-issued grants in the ledger directories this process sees (self_issued_directories()); another owner’s directory is not read. A grant file that cannot be read is logged and left out of the check: it refuses every write under it already, and a file nobody can clear from the chip must not veto every approval.

8. Requests, approval and the stop. A holder asks with a request, <ledger dir>/requests/<id>.json (write_request()), read the way a grant is read (_parse_request(), list_requests()); a web terminal reads the holders’ requests from a read-only bind, REQUESTS_DIR_ENV_VAR. A person acting as the owner approves it (approve_request()): under the owner’s record lock, then the grants directory’s — the one lock order every writer of both keeps — the grant is written under the request’s own id, so the holder waits for exactly that id (approved_grant()). The switch’s own writer, set_switch(), revokes every grant on the machines a stop names inside its record lock (revoke_grants()), so a stop is one gesture and refuses the next write; a stop whose marks cannot be written moves the record’s epoch instead, which ends every grant of that owner. Every lock here is created at 0o660 whatever the umask, because a grants directory is written by several uids through its group. A listing removes grants that ended more than _PRUNE_AFTER_S ago (prune_grants()).

This module imports nothing from osprey and sits above the record and the posture store, which it reads.

The control-context record — one file per identity.

Which machine a deployment is pointed at, how many times that has moved, and what one operator has narrowed are properties of the deployment as that operator holds it, not of any process tree inside it. They live in a single JSON file, RECORD_FILENAME inside the acting identity’s directory under STATE_DIR_NAME (the state directory, state_dir()), and this module is where it is written and read.

The file has exactly one writer at a time — its owner: the web terminal when one is running, otherwise a controls MCP server. Everything else is a reader: every chat session, every notebook kernel, every executor sandbox, every sibling MCP server, and the stdlib-only hooks, which cannot import this module and therefore restate the rules below. Treat them as the contract; a change here is a change there.

1. Where the file is. record_path() — the record sits in the same directory as the posture store, and the root resolves by that store’s rule 1 (osprey_connectors.posture_store.state_dir()) rather than by a second derivation here: a record one process writes and another looks for somewhere else is worse than no record at all. An unresolvable root makes record_path() None, which reads as “no record” and makes write_record() raise — a route surfaces that as store_unavailable rather than writing where no reader will look.

2. What a payload must carry. schema (exactly _SCHEMA_VERSION), target (a member of CONTROL_TARGETS) and generation (a non-negative integer) are the record’s identity. If any of the three is absent, of the wrong type, or unrecognised, there is no record: this is a file that decides whether a real machine is written to, so a hand-edited or future-version payload must not be honoured in part.

The other fields are annotations on that identity and degrade on their own, because each has a meaningful “not stated” value that a reader can act on safely:

  • owner → None, which is ownerless — the state a claim is for. An owner that does not name one of _OWNER_KINDS and a live PID is not an owner anybody should defer to, so reading it as ownerless is what lets the next process take the file over instead of stalling behind a ghost.

  • posture → {}. A mirror of switch kept for old readers, never an input: ControlContext.to_payload() writes sandbox for every machine in CONTROL_TARGETS whose position is off (_posture_mirror()), whatever the record it was built from carried, and no write decision reads it back. A file written before the mirror may still hold an old narrowing; it is parsed by the posture store’s grammar (rule 2 there) and ignored by the verdict.

  • last_switch → None. It is the terminus of the last switch request — applied or refused — and it is carried verbatim. This module owns the block’s shape, because a requester polls it for its own request_id (terminus() builds it, write_terminus() stores it and reads it back); the switch machinery owns what one says. A refusal is a record write that moves nothing else: the same target, the same generation, the same posture, a new last_switch. That is the whole of how a refusal is reported.

  • switch → {}, every machine’s writes off. A per-target map of which only "asked" and "allowed" leaves survive, and a target absent from it is off. The legacy "on" reads as "asked", and any write stores the whole map in the new spelling; any other value is dropped on parse, so a degraded switch can only refuse. switch_position() is the one reader of the map.

  • switch_epoch → None, a record written before epochs existed. An epoch is a time.time_ns() stamp that only moves forward; the person who widens a switch names the epoch they saw, so a stop or a lost record in between makes their gesture stale. None is never “older” than anything.

The schema stays _SCHEMA_VERSION with the two switch fields added: every pre-existing reader, the stdlib hooks included, ignores keys it does not know, so a record written by this version reads unchanged through them.

3. How it is written. write_json_atomic() replaces a file rather than rewriting it, whole through safety_file.atomic_replace, so no reader ever sees half of one and two writers never interleave into one. Every file in this directory is written through it, the record (write_record()) and the per-server reports and requests alike.

The record is written only under its lock: an exclusive fcntl.flock on the sibling file <record path>.lock, derived from the path being written (so path= moves the lock with the file), waited on for a bounded time and then refused with RuntimeError. Inside the lock write_record() re-reads the file on disk and writes the caller’s record with the on-disk switch and switch_epoch substituted: whatever a caller read earlier, no writer but the person’s own switch gesture (set_switch(), which reads, compares and writes in one hold) moves either field, so a target switch or a refusal terminus racing a stop cannot turn a machine back on. A write that finds the record missing or unreadable writes the switch empty and stamps a fresh epoch, never 0. What a caller changes in the other fields, and whether it is still entitled to, remains the owner’s business.

The exclusion holds among processes sharing one kernel — one host, or containers on a Linux host over a bind mount. Across a macOS host and a VM file share flock is not guaranteed to exclude anything; that residual is closed by the sandboxed connector host, not here.

4. When a change is seen. Every read re-stats the file and re-parses on (st_mtime_ns, st_size, st_ino), the same signature the posture store uses and for the same reason: writes arrive as temp+rename, so two of them inside one filesystem clock tick differ by inode when mtime and size do not.

5. Who else lives in that directory. The record says what the deployment is pointed at; it does not say what any one controls server has managed to do about it. That is the per-server report, server_<pid>.json, one file per controls server, written by that server through its publishers and read here (read_report(), live_reports()). A report is an observation, so it degrades field by field around its one identity, server_pid, and a report nobody can parse is skipped rather than fatal — the readers of these files describe a fleet, and one bad file must not blank the others.

6. Whether anything may act. The record says where the deployment is pointed; the reports say who has got there. converged() is the one place those two are compared, and it is what the executor’s stamp, a notebook cell and a controls server’s write tools ask before they touch a machine: a swap in flight stops everyone, a server acquiring its first connector stops only its own session, a server that could not follow stops only its own session, and nothing else stops anybody.

Every file in that directory is named for the process that owns it, which is what lets a reader judge one without opening it: is_process_alive() and sweep_dead() are that rule and its consequence. Liveness lives here, at the bottom, because the record’s owner, the reports’ authors and the request files’ addressees are all judged by it and there must be one answer.

This module imports nothing from osprey and holds no config: it runs inside connector-host children, executor sandboxes and notebook kernels, where the dependency budget is the lean connector chain. The import direction is one-way — the posture store below it, never the reverse at module scope.

The person’s switch gesture — the one writer of switch. Rule 3.

Reads, compares and writes in one hold of the record lock, through the same private writer write_record() uses, so no other write lands between what this compared and what it stored.

Each named target’s move is classified inside the lock, against the map on disk, so a move believed to be a narrowing that raced a stop is judged a widening and refused.

  • A widening (one name moving up off → asked → allowed gates the whole call) requires epoch, the switch_epoch the person saw, and succeeds only when it equals the record’s epoch — a compare-and-swap. It raises StoppedSince carrying the on-disk epoch when the two differ (newer or older) or epoch is None, when the record has no epoch (one is stamped and stamped is set, so the retried gesture succeeds), or when there is no usable record.

  • A narrowing or a no-op applies unconditionally and never refuses. "off" clears each named key, known target or not.

  • "all" (with "off") clears every key and moves the epoch to max(old + 1, time.time_ns()), which makes every widening begun before it stale.

Only a stop moves an existing epoch; a gesture on an epoch-less record stamps a fresh time.time_ns(). Every other field is kept as on disk.

A stop also ends every program authorization (a grant of write_authorization) on the machines it names, or on every machine for "all": inside the same hold of the record lock, after the record is stored, each grant in the authorizations directory beside the record is marked revoked, so the holder’s next write refuses. "all" also moves the epoch, which ends every grant issued under the old one whatever its file says. The marks are written even when no record is there.

A stop fails closed on its marks: when they cannot be written (the grants directory locked past the wait, a lock or a grant file this process cannot open), a stop of named machines moves the epoch as well, in the same hold, so every grant on every machine of this record ends — wider than asked, never narrower — and the stop is taken. The bound has one rule (settle_bound()): the setpoint’s tolerance (absolute, or relative times the demand’s magnitude); with none stated, on the simulator only, the readback’s motion band; a caller’s floor raises the bound and never lowers it. settle() polls each readback through the connector until it is within its bound, and fails closed with SettleTimeoutError when the time runs out. A readback that cannot be reached, is not a channel, or times out raises SettleReadError, which names it, as does one that answers no value; a lost connector raises its own error.

This module imports only the std-lib and osprey_connectors.errors, and takes any connector with an awaitable read_channel(address) whose result carries .value.

async osprey_connectors.settle.settle(connector, landings, *, timeout_s, clock=time.monotonic, sleep=asyncio.sleep)[source]#

Poll each landing’s readback until it is within its bound of its demand.

Every landing is read once per poll until it is inside; a settled landing is not read again. A reading with no value is a failed read; any other reading that is not a finite number is never inside.

Parameters:

  • connector (Any) – Reads each readback with await connector.read_channel(address).

  • landings (Sequence[Landing]) – The landings to wait for.

  • timeout_s (float) – Seconds from the call after which an unsettled landing fails.

  • clock (Callable[[], float]) – The clock the deadline is measured on.

  • sleep (Callable[[float], Awaitable[None]]) – The pause between two polls.

Raises:

  • SettleTimeoutError – A landing was not inside its bound once timeout_s had passed, naming the first such landing in landings order.

  • SettleReadError – A readback read failed with a ChannelError (it cannot be reached, is not a channel, or timed out) or answered no value, naming that readback. Any other failure, a lost connector among them, propagates as itself.
