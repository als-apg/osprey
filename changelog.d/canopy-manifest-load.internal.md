Pin CANOPY to 2174e464 and record the payload's screen viewer at 27e97282. The server keeps its listing of the screens between runs (in `.cache` of the personal store, never in the library), answers the listing from one shared copy off its event loop, and tells the active window on its event stream when the listing or a collection changed, so the viewer no longer asks at an interval and opens a screen from the listing it already holds. A right click on a value a screen computes opens a menu about it. The local authoring recipe for a library now sets `CANOPY_CACHE_DIR`: without it the listing file lands inside the library, which the report check and `osprey build` refuse.
