Optimizer service (engine): the Xopt-driven tuning engine is now part of
OSPREY as `osprey.services.optimizer`, installed with the `optimizer` extra.
An optimization environment is a YAML file of setpoint/readback channels and
observables (a single channel, or the `rms`, `mean` or `max` of several), and
every write it makes goes through the control-system connector, so the write
switch, channel limits and `max_step` apply to each one. A run names its
control target (`va`, `standin` or `live`); a cancelled or failed run writes
its starting values back by default (`on_abort: restore`). An environment can
offer presets, named run setups (variables, search windows, algorithm, length,
objective) that a draft names to fill whatever it leaves unset. Deploying the
service and driving it from the agent come in later releases.
