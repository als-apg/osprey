Application containers that run on the project image (`runtime: osprey`) render through a bundled `app_runtime` compose template, published on loopback only. `osprey build` builds each application package under `apps/<name>/` and each local-path dependency to a wheel and installs it in the build venv and in every project image, resolved together with the framework. Each is bound to its wheel, so no index can serve its name; a wheel that does not fit the image or holds a `.env`, and a distribution named twice, stop the build. `--skip-deps` builds no wheel, so its render's image fails at the missing wheel until a full build.
