The simulator view's records in `osprey_connectors.simulation.records` are now frozen pydantic models instead of TypedDicts, and `SimulatorView.document()`, `seed()` and `scenarios()` return them, validated when each file is first read: read a field by attribute (`scenario.still`, `seed.noise`, `document.channels`) instead of by key, and build one with keywords or `Model.model_validate(mapping)`. A view file whose shape breaks its record is refused as a `ViewSchemaError` naming the key and the reason, when the file is read rather than when a reader reaches the key. An optional block a record does not state reads as its empty default (`()`, an empty mapping or `None`); where absence matters (`noise.absolute`, a wiring record's `default`), ask the record's `model_fields_set`. A document's `schema` field is `schema_id`. The motion envelope, top-off, series and archive functions take these records instead of mappings, so a caller holding a facility seed or event as a mapping validates it first (`SeedRecord.model_validate(seed)`, `ArchiverEvent.model_validate(event)`). `Channel`, `Binding`, `Model`, `Overlap`, `ChannelFault`, `FingerprintComparison`, `SeedKnobs`, `SeedReport` (still mutable), `PlotSeries`, `PlotSpec` and `ScenarioLogEntry` are pydantic models: build them with keywords, copy with `osprey_connectors.model.evolve(record, **changes)` instead of `dataclasses.replace`. `SeedKnobs` checks its knobs when it is built, and its `validate()` method is gone.
