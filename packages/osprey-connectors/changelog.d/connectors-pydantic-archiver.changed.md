`ArchiverMetadata`, `ArchiveExtent`, `ArchiverPairing`, `RelativeTimestamp` and `Landing` are now pydantic models instead of dataclasses. Build them with keyword arguments (`Landing(setpoint=..., readback=..., demand=..., bound=...)`, not `Landing(sp, rb, demand, bound)`); a positional call, an unknown field or a value of the wrong type now raises `pydantic.ValidationError`, a `ValueError`. Strict fields refuse what converts: `ArchiverMetadata.is_archived` takes a `bool` or `None` (not `numpy.bool_`), `ArchiveExtent.channels` a `frozenset` (not a `set`), `RelativeTimestamp.time` a `datetime.time` (not a string). A `float` field given an `int` holds it as a `float`. Read fields with `ArchiverMetadata.model_fields` instead of `dataclasses.fields`; copy a frozen one by rebuilding it. `ArchiverMetadata` stays mutable, each assignment validated. A malformed EPICS Archiver Appliance reply is still refused with `ValueError`, whose message now names the field and the reason (`data.0.secs: Field required`).
